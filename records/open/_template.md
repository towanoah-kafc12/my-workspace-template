# 未解決事項の記録ルール

## 記録する条件

複数の作業に影響し、解決するまで今後の判断や作業がぶれる事項だけを記録します。

次の情報はここへ記録しません。

- 一つの作業内で完結する確認事項や調査待ち
- 対象リポジトリだけに関係する課題
- すでに決まっている事項
- 単なる作業メモや次の作業

これらは対象の`work/`または`repos/`内に残します。

## 記載形式

領域ファイルへ次の形式で追記します。項目を管理するためのIDやfrontmatterは付けません。

```markdown
## タイトル

- 確認日: YYYY-MM-DD
- 影響範囲:
- 内容:
- 次の対応:
```

必要な場合だけ、候補、制約、関連ファイルへのリンクを追加します。

## 記載例

```markdown
## 外部資料の同期対象

- 確認日: 2026-07-29
- 影響範囲: knowledgeを参照する調査と設計
- 内容: SharePointのどの領域を同期対象にするか決まっていない
- 次の対応: PJ資料の配置と権限を確認して対象を決める
```

## 解決後の扱い

- 解決した項目は領域ファイルから削除する
- 解決によって横断的な決定が生じた場合は、`records/decisions/`へ決定と理由を残す
- 解決結果が一つの作業だけに関係する場合は、その作業内へ残す
- 長期的に参照する現在の情報が変わった場合は、該当する`knowledge/`を更新する
- 解決済み項目を保管するためのファイルやディレクトリは作らない

## ファイルを分ける基準

最初は`project.md`へ記録します。次の状態になった領域だけ、`aws.md`や`database.md`などの領域ファイルへ分けます。

- その領域だけを独立して読む機会が増えた
- その領域だけを独立して更新することが増えた
- 関係のない情報まで読む負荷が大きくなった
- ユーザからの指示

一つの領域内に互いにほぼ独立した関心事が育った場合は、その領域だけをディレクトリ化します。単純な行数や件数では分けません。

`records/decisions/`でも、原則として同じ分類軸を使います。ただし、記録がない側に空ファイルを作る必要はありません。
